# 변경의 출처

**커밋에 출처 표식을 요구하는 것은 새로 제안된 규칙이다.** 기존 계약에는 없고
게이트가 강제하지 않으며, 이 하네스의 초기화 커밋 자체도 표식이 없다.

**Intent:** 저장소만 보고서는 어떤 커밋이 어떤 게이트를 지나왔는지 알 수 없다.
카드를 claim 하지 않으면 락도 파일 허용목록도 리뷰어 게이트도 **전부 걸리지 않는데
그것이 diff 에서는 보이지 않는다.** 루프가 카드로 관리하는 작업에 적용되며, 그 밖의
커밋에는 **출처를 밝히는 표식**을 남기는 것으로 족하다.

**Evidence:** 착수 전에 **이미 도는 레인이 있는지** 확인한다(SHOULD) — 승인이 큐
진입을 뜻하지 않고, 카드가 없다고 작업이 안 된 것도 아니다. 부재를 주장하기 전에
최신 상태를 가져와 확인한다: 낡은 사본을 읽고 "없다" 고 말하지 않는다.

**Decision:** 세션이나 레인이 둘 이상이면 **작업 공간을 나눈다** — 별도 브랜치,
별도 디렉터리, 또는 워크트리 중 계약이 허용하는 것이면 된다. git 의 브랜치는
워크트리 단위 전역 상태여서, 한 세션이 옮기면 나머지가 조용히 따라가고 커밋이 남의
브랜치 위에 떨어진다. 이 하네스에서 카드별 격리는 `LOOP_WORKTREE=1` 로 켜는 선택
사항이므로, **병렬로 돌릴 것이면 켠 뒤에 돌린다.** 워크트리를 나눈 뒤에는 상태
디렉터리를 주 저장소로 고정한다 — 나누기만 하면 백로그가 갈라져 문제가 옮겨갈 뿐이다.

**Execution:** 기준 브랜치는 **독립 리뷰를 거친 변경만** 받는다(MUST). 원격을 쓰는
저장소에서는 그것이 브랜치 → PR → squash 병합이다 — 다만 **이 하네스가 내보내는
병합 스크립트는 리뷰 상태를 확인하지 않으므로**, 강제하려면 origin 의 브랜치 보호를
켜야 한다(사람의 결정). 커밋은 커밋은 출처를 밝힌다 — 카드
식별자 또는 명시적인 임시 작업 사유. 병합 뒤에는 원격 브랜치가 **정말 지워졌는지
확인한다**: 워크트리가 잡고 있으면 삭제가 조용히 실패한다.

**Recovery:** 기준 브랜치에 직접 미는 길은 둘이다. **프로덕션 롤백**은 revert 커밋
하나를 base 로 바로 민다 — 장애 중에 PR 검사를 기다리는 것은 롤백의 목적을 없앤다.
그리고 **사람이 의도적으로 올릴 때** 훅의 우회 플래그가 있다 — 훅은 경계가 아니라
실수를 막는 안전장치이고, 진짜 경계는 origin 의 브랜치 보호다. 장애 중에 PR 검사를 기다리는 것은 롤백의 목적을 없애고, 실리는 것은 revert
커밋 하나뿐이다.

**이 하네스의 기본 경로는 로컬 병합이라는 것을 알고 있어야 한다.** `worktree.ts
integrate` 는 원격이 없어도 카드 브랜치를 base 로 merge 하고, 무인 실행이라고 해서
그것을 거부하지 않는다. 즉 PR·squash 를 실제로 강제하는 것은 이 하네스가 아니라
**origin 의 브랜치 보호**다 — 켤지는 사람이 정한다. 훅이 막았다면 우회 플래그를
찾기 전에 **왜 막혔는지** 본다.

**Failure modes:** **출처 없이** 커밋하는 것 — 카드 식별자도 명시적 `Ad-hoc:` 사유도
없는 커밋. 루프 밖의 커밋에 카드가 없는 것 자체는 위반이 아니다. 공유 워크트리에서 여러 세션을 돌려 미커밋
작업이 무관한 커밋에 쓸려 들어가는 것. 로컬에서 기준 브랜치에 merge 한 뒤 push 해서
리뷰가 붙을 자리를 없애는 것. `--no-verify` 나 훅 경로 우회로 게이트를 끄는 것.
병합 뒤 남은 원격 브랜치를 확인하지 않는 것.
