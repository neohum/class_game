# 자율성 3계층

> 이 하네스가 **무엇을 스스로 결정하고, 무엇을 다른 모델에게 물어보고, 무엇을
> 사람에게 넘기는지**에 대한 정책. 설정이 아니라 **작업의 분류**다.
> 강제 지점은 `scripts/loop/autonomy.ts`와 아래 표의 모듈들이다.

## 왜 계층인가

"완전 자율"의 실패 모드는 크래시가 아니라 **성공했다고 보고된 잘못된 결과**다.
그리고 자동 게이트가 잡는 오류와 사람이 잡는 오류는 종류가 다르다 — 게이트는
*규칙 위반*을 잡고, 사람은 *잘못된 전제*를 잡는다. 문법도 테스트도 통과하는데
"내가 본 것이 실제 상태다"라는 전제가 틀린 경우, 그걸 잡는 자동 검사는 없다.

그래서 자율성을 늘리는 방법은 게이트를 **제거**하는 게 아니라, 사람이 하던 판단을
**기계 검증으로 교체**하는 것이다. 그리고 교체가 불가능한 것만 사람에게 남긴다.

## 계층

### Tier 1 — 혼자 결정한다

되돌릴 수 있는 작업. 카드별 워크트리 안, iteration cap·명령 타임아웃·health
게이트·예산 상한 안. **사람도 두 번째 모델도 개입하지 않는다.**

| 경계 | 강제 지점 |
| --- | --- |
| 최대 단계 수 | `graph.ts` (`maxSteps`) |
| 카드당 반복 횟수 | `ralph-loop.ts` (`LOOP_MAX_ITERS`, 기본 6) |
| 명령 타임아웃 | `ralph-loop.ts` (`run()`) |
| 편집 격리 | `worktree.ts` (`LOOP_WORKTREE=1`), `swarm.ts` |
| 지출 상한 | `budget.ts` (`HARNESS_BUDGET_*`) |

### Tier 1.5 — 강한 레인이 계획하고, 싼 레인이 친다 (architect/editor)

Aider가 측정한 분할이다: 강한 모델이 **변경을 추론**하고 저렴한 모델이 **적용**하면,
저렴한 모델 혼자 하는 것보다 낫고 강한 모델 혼자 하는 것보다 훨씬 싸다.

`LOOP_PLAN`: `auto`(기본) · `on` · `off`.

**`auto`는 플래너가 대량 레인(bulk lane)일 때 계획한다.** 그때 설계 패스는
배급 중인 쿼터를 쓰지 않으므로, Aider의 결과가 그대로 선다 — 프런티어 모델은
추론에 강하지만 구조화된 diff를 자주 망가뜨리고, 저렴한 모델은 diff에 정확하지만
계획이 약하다.

플래너가 유료 레인이면 `auto`는 거절한다. 예전 기본값은 무조건 계획했고, 2초짜리
e2e 테스트를 88초와 실제 쿼터로 바꿔놨다. `on`이 그 청구서를 의도적으로 받는
방법이다.

**계획은 저자를 한 명 늘린다.** 플래너가 파일과 접근법을 골랐으므로, 리뷰어는
빌더와 플래너 **양쪽 모두와** 독립이어야 한다. 자기 계획의 결과를 리뷰하는 것은
자기 diff를 리뷰하는 것과 같은 false consensus다. 그래서 `pickPlanner`는 **독립
리뷰어가 남지 않게 되는 플래너를 아예 고르지 않는다** — 분할이 게이트를 굶길 수는
없다.

계획은 카드당 한 번 작성된다. health red는 *편집*이 틀렸다는 뜻이지 접근법이
틀렸다는 뜻이 아니기 때문이다. 다만 품질 회전이 발동하면(같은 레인이 반복 실패)
계획도 함께 버려서, 다음 레인이 실패한 계획을 다시 타이핑하지 않는다.

### Tier 2 — 다른 프로바이더가 동의해야 한다

**한 모델의 말만으로는 아무것도 나가지 않는다.** 같은 가중치는 같은 맹점을 갖기
때문이다.

`pickReviewer()`는 빌더와 독립적인 프로바이더가 없으면 `null`을 반환하고,
`nodeReview`는 카드를 진행시키는 대신 **양보**한다. 빌더가 유일하게 남은
에이전트여도 자기 작업에 서명할 수 없다. 독립성은 에이전트 이름이 아니라 **신뢰
도메인**으로 판정하므로, 두 레인이 같은 모델 가중치를 쓰면 몇 대의 기계에서 돌든
하나의 의견이고 서로를 리뷰할 수 없다.

교차 모델 challenge(`FRAMEIN_CHALLENGE=1`)는 **이 보장에 더해지는 두 번째 의견**
이지 보장 자체가 아니다. 일반 카드에서 기본 OFF인 이유는 리뷰어가 이미 독립·적대적
이기 때문 — 같은 보장에 두 번 지불하지 않는다. 고위험 diff에서는 항상 실행되고
BLOCK이 카드를 멈춘다.

### Tier 3 — 사람이 탭한다

**되돌릴 수 없고, 외부로 나가고, 비용이 비대칭인** 것. 모델 확신도와 무관하게
소유자에게 간다.

| 범주 | 탐지 |
| --- | --- |
| auth / 권한 | `framein.ts` 경로 스코어 (`crit`) |
| 시크릿 / 자격증명 | 〃 |
| 스키마 / 마이그레이션 | 〃 |
| 결제 / 과금 | 〃 |
| 프로덕션 배포 | `release-policy.ts` (staging → canary → production, 점프 금지) |
| 데이터 계약 위반 | `data-contract.ts` (fail-closed) |

## 대량 레인 (bulk lane)

`HARNESS_BULK_LANE`(기본 `antigravity`)은 **쿼터를 배급하지 않는 레인**을 선언한다.

이 루프에서 몇 가지는 순전히 "두 번째 의견의 비용" 때문에 선택사항이었다 — 일반
카드의 교차 모델 challenge, 빌더 앞의 설계 패스. **그건 코드가 아니라 구독에 관한
질문이고, 운영자마다 답이 다르다.** 그래서 호출 지점마다 다시 따지는 대신 여기서
한 번 선언하고, 작업이 그 레인에 떨어질 때 해당 기능을 기본 ON으로 돌린다.

| 기능 | 대량 레인이 맡을 때 | 그 외 |
| --- | --- | --- |
| 교차 모델 challenge (일반 카드) | **기본 ON** | 옵트인 (`FRAMEIN_CHALLENGE=1`) |
| architect/editor 분할 | **기본 ON** (`LOOP_PLAN=auto`) | 옵트인 (`LOOP_PLAN=on`) |
| 정기 타이머 잡 6종 | 항상 (`lanes.ts`) | — |

**이것이 절대 완화하지 못하는 것: 독립성.** 대량 레인도 자기 작업은 검증할 수
없다. challenge 기본값은 "대량 레인이 존재하는가"가 아니라 **"빌더와 독립인 대량
레인 challenger가 실제로 가능한가"**를 읽고, 플래너 선택도 빌더가 대량 레인이면
`null`을 낸다. 쿼터는 더 많은 의견을 살 뿐, 자기 자신의 두 번째 의견이 될 권리를
사지는 못한다.

`HARNESS_BULK_LANE=none`이면 전부 옵트인으로 돌아간다.

## 계층을 가로지르는 불변식: 안전 우회는 대화형 전용

여러 가드가 **사람에게는 합리적인 탈출구**를 갖고 있다 — 디버깅 중 Docker를
건너뛰는 `HARNESS_SANDBOX_MODE=host`, 리팩터링 중 경로 스코어링을 끄는
`FRAMEIN_RISK=off`.

우회를 켠 사람은 그 자리에서 결과를 본다. **셸 프로파일에서 그걸 물려받은 24/7
팩토리는 보지 않고, 몇 주 동안 계속 쓴다.**

그래서 무인 실행은 스스로를 선언하고(`markUnattended()`), 선언된 실행은 안전
우회를 쓸 수 없다:

```
ralph-loop.ts / factory.ts  (isMainModule 블록)
        │  markUnattended()   → HARNESS_UNATTENDED=1
        ▼
FRAMEIN_RISK=off            → 무시 + guard 이벤트      ← 가드는 켜진 채로 진행
HARNESS_PLAN_GATE=off       → 무시 + guard 이벤트, 기본값(risk)으로 복귀
HARNESS_SANDBOX_MODE=host   → HARNESS_UNATTENDED_ALLOW_HOST=1 없으면 거부
                              있으면 진행 + 경고 + guard 이벤트
```

`HARNESS_PLAN_GATE=off`가 같은 취급을 받는 이유는 단순하다. 터미널 앞의 사람은
계획서 없이 위험한 카드를 만져도 된다 — **그 사람이 계획이다.** 무인 실행에는
그 역할을 할 주체가 없다. 거부는 `strict`로 올리는 것이 아니라 기본값 `risk`로
되돌리는 것이다: 우회를 거절하는 것과 규칙을 강화하는 것은 다른 일이다
([`PLAN_DOCS.md`](PLAN_DOCS.md)).

두 처리가 다른 이유: 리스크 플로어는 무시하고 진행해도 되지만, **샌드박스 실패는
나중에 잡을 방법이 없다.** 다른 가드는 나쁜 diff를 통과시키고 뒤의 게이트가 잡을
수 있지만, 샌드박스는 에이전트를 상자 밖으로 내보낸다.

그렇다고 호스트 실행을 전면 금지하지는 않는다 — Docker가 없는 박스나 전용 신뢰
머신에서 루프를 돌리는 건 정당하다. (이 가드의 첫 버전은 전면 거부였고 루프 자신의
e2e 테스트를 깨뜨렸다. 그게 "절대 금지"가 틀린 규칙이라는 증거였다.) 규칙은
**"절대 안 됨"이 아니라 "실수로는 절대 안 됨"**이다.

`HARNESS_ALLOW_HOST_EXEC=1`은 로컬 개발용으로 문서화돼 있어 셸 프로파일에 영원히
남기 쉽다. `HARNESS_UNATTENDED_ALLOW_HOST=1`은 **"무인 루프를 샌드박스 밖에서
돌린다"는 뜻밖에 없어서** 습관으로 설정되지 않는다. 그리고 그렇게 돌 때는 시작
시점에 경고와 `guard` 텔레메트리를 남긴다 — 몇 주간의 비격리 운영은 셸 히스토리가
아니라 트레일에서 읽혀야 한다.

선언은 **추론이 아니라 명시**다. TTY 검사나 부모 프로세스 추측은 양방향으로
틀린다 — 출력을 파이프로 넘기는 사람도 사람이고, PTY를 가진 팩토리도 팩토리다.

새 우회를 추가하면 `autonomy.ts`의 `GOVERNED_OPT_OUTS`에도 추가해야 한다.
`tests/autonomy.test.ts`가 선언만 되고 아무도 참조하지 않는 항목을 실패시킨다.

## 자율성을 더 늘리려면

게이트를 끄는 게 아니라 사람의 판단을 기계 검증으로 옮긴다:

| 사람이 하던 것 | 교체 |
| --- | --- |
| "이거 맞나?" | 실행 가능한 수용 기준 `AC-*` + `Tests` 명령 |
| "너무 많이 쓰는데" | `budget.ts` 상한 |
| "이 모델 계속 헛소리하네" | 품질 기반 레인 회전 (연속 red health) |
| "되돌려" | 워크트리 격리 + 커밋 되돌리기 + 카나리 롤백 |
| **"이 전제가 틀렸는데"** | **교체 불가 — Tier 3로 남는다** |

두 번째 축은 **되돌리기를 싸게 만들어 게이트를 낮추는 것**이다. 워크트리, 브랜치,
카나리. 되돌리기가 쌀수록 Tier 1이 넓어진다.
