# ADR 0028: Jev(System One)로 diff 내용 기반 리스크 채점

- **상태:** 채택 (Accepted)
- **날짜:** 2026-09-20
- **결정자:** 저장소 소유자(승인), lead(Claude)
- **관련:** `plans/jev-decision-layer.plan.md`, `docs/jev-decision-layer.md`, `scripts/loop/jev-risk.ts`, ADR-0027

---

## 배경

`scripts/loop/framein.ts`의 `riskScore()`는 하네스의 blast-radius 판정 근거이고,
그 값이 `persona-approve.ts`의 배포 게이트로 흘러 "사람 탭이 필요한가"를 가른다.

이 함수는 **파일 경로에 대한 정규식 7개**로만 채점한다. diff 본문을 읽지 않는다.
결과적으로 두 방향의 오류가 구조적으로 발생한다.

- **거짓 양성:** `payment_utils.ts`의 주석 수정이 `high`로 채점되어 불필요하게
  사람을 깨운다. 비용 = 한 번의 확인.
- **거짓 음성:** `server.ts` 안에서 권한 검사를 삭제해도 `low`다. 파일 이름에
  `auth`가 없기 때문이다. 비용 = **Tier 3 게이트를 통과한 권한 우회의 자율 배포.**

거짓 음성이 결정의 이유다. 민감한 이름이 붙지 않은 파일 속 변경은 현재 하네스의
어떤 자동 게이트도 잡지 못한다.

LLM CLI(`invoke-claude.ts` 등)를 매 판정마다 부르는 방법은 이미 기각되어 있다 —
게이트 경로에서 수 초~수십 초의 지연과 세션 비용을 감당할 수 없어서, 애초에
정규식으로 때운 자리이기 때문이다.

## 결정

TypeSafe AI의 **Jev(System One 모델)**를 정규식 위에 **단조(monotonic) 합성**으로
얹는다. Jev는 텍스트를 생성하지 않고 타입이 정해진 값과 보정된 확률을 돌려주며
(70~500ms, 입력 $0.042/MTok, 출력 무료), 이 자리의 제약 — 빨라야 하고, 구조적
답이어야 하고, 싸야 한다 — 에 정확히 맞는다.

```
최종 리스크 = max(정규식 판정, Jev 판정)
```

### 이 결정을 안전하게 만드는 네 가지 불변식

1. **단조성.** Jev는 판정을 **올리기만** 한다. 정규식 `high`는 Jev가 확신을 갖고
   반대해도 `high`다. 이 레이어를 켜는 것이 기존 보호를 약화시킬 수 없다.
   `jev-risk.ts`의 `maxLevel()` 한 곳에서 강제하고 단위 테스트로 증명한다.
2. **모든 실패는 정규식으로 폴백.** 키 없음·타임아웃·비정상 응답·기능 꺼짐 모두
   정규식 결과를 그대로 반환한다. 이는 게이트를 *여는* 것이 아니라 **Jev 도입
   이전 동작**이므로 fail-closed 원칙과 충돌하지 않는다.
3. **기본 off, 옵트인.** `FRAMEIN_JEV=1`이 있어야만 호출한다.
4. **시크릿 스크러빙은 최선의 노력이다 — 보장이 아니다.** 모든 hunk가
   `redact.ts` → `scrubForEgress()` 두 단계를 거친다. 두 번째가 필요한 이유는
   측정됐다: `redact.ts`의 이름-접미사 규칙으로는 AWS 키·PEM 블록·`client_secret`·
   맨 `password:`가 그대로 통과한다. 그래도 패턴 매칭이므로 새 형식은 빠질 수 있고,
   확실히 막아야 하면 `JEV_REDACT_STRICT=1`이 fail-closed로 본문을 버린다.

### 하지 않기로 한 것

- **생성이 필요한 판정은 그대로 둔다.** `persona-approve`의 페르소나 판정,
  `assess-shortcomings`의 카드 생성, `harness-radar`의 웹 조사는 텍스트 생성이
  필요하고 Jev는 생성하지 못한다.
- **SDK를 설치하지 않는다.** `@typesafe-ai/sdk`는 실재하지만(v0.6.0) 이 저장소는
  런타임 의존성 0개가 계약이고, Jev는 엔드포인트 하나에 대한 POST 한 번이다.
  `notify-resend.ts` 선례대로 전역 `fetch`를 쓴다.
- **`route.ts`(에이전트 라우팅)와 훅 경로는 범위 밖.** 오라우팅 비용이 낮고,
  훅은 매 프롬프트마다 돌아 네트워크 실패에 막히면 안 된다.
- **`sloppiness.ts`는 건드리지 않는다.** 의도적으로 "AI-as-judge"가 아니도록
  설계된 결정적 정적 지표다.

## 결과

### 얻는 것
- 파일 이름에 의존하지 않는 blast-radius 판정. 거짓 음성 구멍이 닫힌다.
- 비용은 카드 1,000장에 약 $0.34, 지연은 한 번의 70~500ms. 게이트가 이미
  `health.sh`(수십 초)를 돌리므로 무시 가능하다.

### 치르는 것 — 솔직하게
- **코드 diff가 제3자 API로 나간다.** 이 저장소가 소스 코드를 외부 HTTP로 보내는
  첫 경로다(기존 네트워크 호출은 Telegram/Resend 알림 텍스트, Infisical 시크릿
  동기화뿐). 그래서 기본 off이고, 스크러빙은 2단계이며(그럼에도 보장이 아니라
  최선의 노력이고, 확실히 막으려면 `JEV_REDACT_STRICT=1`), 조직 정책에 따라
  영영 켜지 않는 것도 정당한 선택이다.
- **외부 서비스 의존이 하나 늘어난다.** 단, 장애 시 정규식으로 되돌아갈 뿐이므로
  루프를 멈추지는 않는다.
- **임계값과 모델 버전이 유지보수 대상이 된다.** `JEV_MODEL`을 `jev-latest`가
  아닌 고정 버전으로 두는 이유이며, 임계값(0.45)은 Step 4의 혼동행렬 위에서만
  조정한다.

### 열어 둔 것
`plans/jev-decision-layer.plan.md`의 Step 4(거짓 음성 측정)가 **기본 활성화의
전제 조건**이다. 측정 결과가 "거짓 음성 절반 이하 감소, 거짓 양성 2건 이하 증가"를
넘지 못하면 코드는 남기되 기본 off를 유지한다. Step 5(`persona-approve` 적용)도
그 측정 이후로 미뤄져 있다.
